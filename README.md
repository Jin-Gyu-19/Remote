# 원격지원 (Remote Support)

이메일 링크 하나로 원격지원을 시작하는 시스템. 피지원자는 **프로그램 실행 방법 안내나 접속 코드 불러주기 없이** 링크만 누르면 된다.

원격제어 엔진은 [RustDesk](https://github.com/rustdesk/rustdesk)를 자체 호스팅해서 사용하고,
"링크 원클릭" 경험은 이 저장소의 **세션 발급 서버**가 담당한다.

## 구성

| 구성요소 | 역할 | 위치 |
|---|---|---|
| 세션 발급 서버 | 링크 생성·메일 발송·세션 상태 관리 | `server/` |
| RustDesk 서버 (hbbs/hbbr) | ID 등록·시그널링·릴레이 | `deploy/docker-compose.yml` |
| 지원자 대시보드 | 링크 발송 및 접속 | `server/public/index.html` |
| 피지원자 안내 페이지 | 동의 → 연결 | `server/src/landing.js` |

## 연결 흐름

1. 지원자가 대시보드에서 상대 이메일을 입력하고 **링크 발송**
2. 상대가 메일의 버튼을 클릭 → 안내 페이지에서 **동의**
3. `rustdesk://` 딥링크로 지원 프로그램이 실행됨
4. 접속 정보가 서버로 전달되고, 지원자 대시보드에 **연결** 버튼이 활성화됨

> 3~4단계는 현재 안내 페이지에서 ID/비밀번호를 수동 입력하는 방식으로 동작한다.
> 커스텀 클라이언트를 적용하면 이 부분이 자동화되어 완전한 원클릭이 된다. (아래 로드맵 참고)

## 개발 환경에서 실행

```bash
npm install
cp .env.example .env        # 최소한 ADMIN_TOKEN 은 변경할 것
npm start
```

SMTP를 설정하지 않으면 메일 대신 **콘솔에 링크가 출력**되므로 자격증명 없이도 전체 흐름을 검증할 수 있다.

- 지원자 대시보드: http://localhost:3000
- 상태 확인: http://localhost:3000/healthz

## RustDesk 서버 올리기

```bash
cd deploy
cp .env.example .env        # RELAY_HOST 를 공인 IP/도메인으로 수정
docker compose up -d
docker compose logs hbbs | grep -i key   # 공개키 확인 (클라이언트 설정에 필요)
```

방화벽에서 다음 포트를 열어야 한다. **21116/UDP 를 빠뜨리면 연결되지 않는다.**

| 포트 | 프로토콜 | 용도 |
|---|---|---|
| 21115 | TCP | NAT 타입 테스트 |
| 21116 | TCP + **UDP** | ID 등록 / 시그널링 |
| 21117 | TCP | 릴레이 |
| 21118, 21119 | TCP | 웹소켓 (선택) |

### 클라이언트 설정

RustDesk 클라이언트 → 설정 → 네트워크 → ID/릴레이 서버에 위 서버 주소와 Key를 입력한다.
사내 배포 시에는 이 값을 미리 넣어 빌드하거나 설정 파일로 배포하면 사용자가 입력할 필요가 없다.

## 무료 호스팅

RustDesk 서버는 매우 가벼워 무료 티어로 충분하다. **Oracle Cloud Always Free**(기간 제한 없음, ARM 인스턴스)를 권장한다.
가입 시 본인확인용 카드 등록이 필요하고, 인스턴스 생성 후 보안 목록(Security List)에서 위 포트를 직접 열어야 한다.

## 보안

원격 접속 도구이므로 다음을 기본 적용한다.

- 링크 토큰은 256비트 난수이며 조회 시 상수 시간 비교를 사용한다
- 링크는 기본 15분 후 만료되고, 종료된 세션은 재사용할 수 없다
- 접속 전 피지원자의 **명시적 동의 화면**을 반드시 거친다
- 운영 API는 `ADMIN_TOKEN` 으로 보호된다 — 배포 전 반드시 변경할 것
- 세션 만료/종료 시 저장된 접속 비밀번호를 삭제한다
- 실제 배포 시 반드시 HTTPS 뒤에 둘 것
