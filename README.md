# 원격지원 (Remote Support)

이메일 링크 하나로 원격지원을 시작하는 시스템. 피지원자는 **프로그램 실행 방법 안내나 접속 코드 불러주기 없이** 링크를 누르고 회사 계정으로 로그인하면 된다.

원격제어 엔진은 [RustDesk](https://github.com/rustdesk/rustdesk)를 자체 호스팅해서 쓰고,
"링크 원클릭" 경험과 신원 확인은 이 저장소의 **세션 발급 서버**가 담당한다.

## 설계의 핵심

**기기를 미리 등록하지 않는다.** 접속 대상은 *인증된 사용자가 링크를 연 바로 그 PC* 다.
사내 PC 에 배포된 작은 핸들러가 그 순간 자기 RustDesk ID 를 서버에 알려준다.
덕분에 관리할 기기 목록이 없고, 한 사람이 노트북과 데스크톱을 오가도 항상 지금 쓰는 PC 가 대상이 된다.

**승인은 비밀번호가 아니라 수락 클릭으로 한다.** Intune 으로 `approve-mode=click` 을 배포하므로
서버가 보관하는 접속 비밀번호가 없다.

## 구성

| 구성요소 | 역할 | 위치 |
|---|---|---|
| 세션 발급 서버 | 링크 생성·메일 발송·세션 상태 관리 | `server/src/index.js` |
| 회사 계정 로그인 | Entra ID 로 링크 수신자 본인 확인 | `server/src/auth.js` |
| 지원자 대시보드 | 링크 발송 및 접속 | `server/public/index.html` |
| 피지원자 안내 페이지 | 로그인 → 동의 → 연결 | `server/src/landing.js` |
| RustDesk 서버 (hbbs/hbbr) | ID 등록·시그널링·릴레이 | `deploy/docker-compose.yml` |

## 연결 흐름

1. 지원자가 대시보드에서 상대 이메일을 입력하고 **링크 발송**
2. 상대가 메일의 버튼을 클릭 → **회사 계정으로 로그인** (초대받은 계정과 다르면 차단)
3. **동의** 버튼 한 번
4. 그 PC 의 핸들러가 자기 접속 정보를 서버에 전달 → 지원자 대시보드에 **연결** 버튼 활성화
5. 지원자가 연결 → 상대 화면의 **수락** 팝업 → 연결 완료

핸들러가 없는 기기(주로 외부 게스트)는 4단계에서 자동으로 직접 입력 화면으로 넘어간다.

### 외부 지원

Entra B2B **게스트로 초대**해 같은 로그인 흐름을 태운다.
게스트 계정의 UPN 은 `user_domain.com#EXT#@tenant.onmicrosoft.com` 형태로 변형되므로,
서버가 원래 메일 주소로 되돌려 초대 대상과 비교한다.

## 개발 환경에서 실행

```bash
npm install
cp .env.example .env        # 최소한 ADMIN_TOKEN 은 변경할 것
npm start
```

- 지원자 대시보드: http://localhost:3000
- 상태 확인: http://localhost:3000/healthz

자격증명 없이도 전체 흐름을 검증할 수 있도록 두 가지가 대체 동작한다.

- **SMTP 미설정** → 메일 대신 콘솔에 링크 출력
- **Entra 미설정** → 계정을 직접 입력하는 개발용 로그인 화면

둘 다 실제 배포에서는 반드시 설정해야 하며, 미설정 시 기동 로그에 경고가 남는다.

## Entra ID 앱 등록

Azure 포털 → 앱 등록에서 다음을 준비한다.

- 리디렉션 URI(웹): `https://support.example.com/auth/callback`
- 클라이언트 비밀 발급 → `ENTRA_CLIENT_SECRET`
- 위임된 권한: `openid`, `profile`, `email`

## RustDesk 서버 올리기

```bash
cd deploy
cp .env.example .env        # RELAY_HOST 를 공인 IP/도메인으로 수정
docker compose up -d
```

방화벽에서 다음 포트를 열어야 한다. **21116/UDP 를 빠뜨리면 연결되지 않는다.**

| 포트 | 프로토콜 | 용도 |
|---|---|---|
| 21115 | TCP | NAT 타입 테스트 |
| 21116 | TCP + **UDP** | ID 등록 / 시그널링 |
| 21117 | TCP | 릴레이 |
| 21118, 21119 | TCP | 웹소켓 (선택) |

RustDesk 서버는 가벼워서 무료 티어로 충분하다. **Oracle Cloud Always Free**(기간 제한 없음)를 권장한다.

## Intune 배포 (유지보수 업체 전달용)

사내 PC 에 다음을 배포한다. 상세 정책 문서는 별도 작성 예정.

- RustDesk 클라이언트 + 자체 서버 주소·Key 내장
- **승인 방식을 '수락 클릭'으로 고정** (`approve-mode=click`)
- `supportlink://` 프로토콜 핸들러 — 링크 클릭 시 실행되어 아래 API 를 호출한다
- Defender 예외, 서비스 모드 설치

핸들러가 호출하는 API:

```
POST /api/s/<링크토큰>/agent
{ "rustdeskId": "482913756", "hostname": "BDO-NB-0417" }
```

세션 토큰이 곧 인가 수단이며, **로그인과 동의를 마친 세션에서만** 접수된다.

## 보안

원격 접속 도구이므로 다음을 기본 적용한다.

- 링크 토큰은 256비트 난수이며 조회 시 상수 시간 비교를 사용한다
- 링크는 기본 15분 후 만료되고, 종료된 세션은 재사용할 수 없다
- **회사 계정 로그인을 통과해야만** 동의·접속 정보 전달이 가능하다
- 초대 대상과 다른 계정으로 로그인하면 차단되고, 대시보드에 경고로 표시된다
- 접속 전 피지원자의 **명시적 동의 화면**을 반드시 거친다
- 사내 경로는 접속 비밀번호를 사용하지 않는다 — 서버가 보관하는 비밀번호가 없다
- 운영 API 는 `ADMIN_TOKEN` 으로 보호된다 — 배포 전 반드시 변경할 것
- 실제 배포 시 반드시 HTTPS 뒤에 둘 것
