# 딥링크 검증 절차

이 프로젝트에서 **가장 먼저 확인해야 할 미검증 항목**. 결과에 따라 개발 범위가 크게 달라진다.

- 공식 클라이언트만으로 링크 자동 연결이 된다면 → **Rust 코드 수정 불필요**, 서버 작업만으로 완성
- 안 된다면 → 커스텀 클라이언트 빌드가 필요하며, 어느 부분을 패치할지 이 테스트로 특정한다

Windows PC 2대(또는 PC 1대 + 가상머신)가 필요하다.

## 준비

1. RustDesk 서버를 띄운다 (`deploy/docker-compose.yml`)
2. 양쪽 PC에 공식 RustDesk 클라이언트를 설치하고, 설정에서 ID/릴레이 서버와 Key를 자체 서버로 지정
3. 서로 정상 연결되는지 먼저 확인 (이게 안 되면 방화벽/포트 문제 — 특히 **21116/UDP**)

## 테스트 항목

### 1. 프로토콜 등록 여부
브라우저 주소창 또는 실행창(Win+R)에 입력:
```
rustdesk://
```
- [ ] 클라이언트가 실행되는가?

### 2. 특정 ID로 연결 시도
```
rustdesk://connection/new/123456789
```
(위 숫자를 상대 PC의 실제 ID로 교체)
- [ ] 클라이언트가 실행되면서 해당 ID로 **연결 창이 바로 뜨는가?**
- [ ] 비밀번호 입력 단계에서 멈추는가?

### 3. 비밀번호 자동 전달 가능 여부
아래 형태들이 동작하는지 각각 확인한다. (버전에 따라 지원 여부가 다름)
```
rustdesk://connection/new/123456789?password=abcd
rustdesk://123456789
```
- [ ] 비밀번호까지 전달되어 **바로 연결**되는가?

### 4. 고정 비밀번호(무인 접속) 경로
피지원자 PC에서 설정 → 보안 → 고정 비밀번호를 지정한 뒤,
지원자 PC에서 2번 딥링크로 접속:
- [ ] 저장된 비밀번호로 자동 연결되는가?
- [ ] 첫 연결 이후 비밀번호가 기억되어 다음부터는 즉시 연결되는가?

## 결과 해석

| 결과 | 다음 단계 |
|---|---|
| 3번이 동작 | 서버에서 링크만 만들면 끝. **커스텀 클라이언트 불필요** |
| 2번까지만 동작 | 사내 PC는 4번(고정 비밀번호) 방식으로 원클릭 달성 가능 |
| 2번도 안 됨 | 커스텀 클라이언트에서 URL 스킴 핸들러를 직접 구현해야 함 |

## 참고

사내 배포 시에는 4번 방식이 현실적으로 가장 안정적이다.
PC마다 고정 비밀번호를 부여하고 세션 발급 서버가 이를 관리하면,
피지원자는 **링크 클릭만**, 지원자는 **대시보드의 연결 버튼만** 누르면 된다.
